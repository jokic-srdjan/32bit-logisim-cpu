# CPU Architecture

## Overview

This project implements a custom **32-bit CPU in Logisim Evolution** based on a MIPS-inspired architecture.

The processor executes 32-bit machine instructions stored in the instruction ROM. Each instruction is decoded by the **Control Unit**, which generates the control signals required to coordinate the Program Counter, register file, execution units, RAM and write-back path.

The basic execution path is:

```text
Instruction ROM
      │
      ▼
Instruction
      │
      ▼
Control Unit
      │
      ├──────── Control Signals ────────┐
      │                                 │
      ▼                                 ▼
Register File                     Program Counter
      │
      │ operands
      ▼
 Integer Unit
 ┌────┼───────────┐
 │    │           │
 ▼    ▼           ▼
ALU  Multiplier  Divider
 │
 ▼
Result
 │
 ├────────► Register File
 │
 └────────► Data RAM
```

## Instruction ROM

Programs are stored as **32-bit machine instructions** in the instruction ROM.

The machine code is generated by the custom Python assembler and loaded into the ROM before program execution.

The Program Counter determines which instruction is read from the ROM.

## Control Unit

The Control Unit is responsible for decoding the current instruction and controlling the processor.

Depending on the instruction, it generates the signals required to control:

- register selection and write-back
- ALU operation selection
- multiplication and division
- RAM reads and writes
- immediate values
- branches and jumps
- Program Counter updates

The Control Unit therefore connects the instruction encoding defined by the ISA with the actual hardware operations of the CPU.

## Register File

The CPU contains **32 general-purpose 32-bit integer registers**.

The register file provides source operands to the execution units and receives results through the write-back path.

Register addresses are 5 bits wide, allowing 32 registers to be addressed.

The register naming convention follows a MIPS-inspired layout, including `$zero`, `$v0`, `$a0`, `$t0`, `$s0`, `$sp` and `$ra`.

## Integer Unit

The **Integer Unit** combines the processor's integer execution hardware.

It consists of:

```text
Integer Unit
│
├── ALU
├── Combinational Multiplier
└── Combinational Divider
```

The different execution paths are connected to a common result path so that the Control Unit can select the result required by the current instruction.

## ALU

The 32-bit ALU combines several classes of operations:

```text
ALU
├── Arithmetic Unit
├── Logic Unit
├── Comparator Unit
└── Shifter Unit
```

### Arithmetic Unit

Performs basic integer arithmetic such as addition and subtraction.

### Logic Unit

Performs bitwise logical operations such as AND, OR, XOR, NAND, NOR and XNOR.

### Comparator Unit

Performs integer comparisons including:

- equal
- not equal
- less than
- greater than
- less than or equal
- greater than or equal

### Shifter Unit

Performs shift and rotate operations on 32-bit values.

## Multiplier

Integer multiplication is implemented using a dedicated **combinational 32-bit multiplier**.

Unlike an iterative multiplier, the multiplication is constructed as combinational logic and produces its result through the corresponding hardware path without executing a software multiplication algorithm.

## Divider

Integer division is implemented using a dedicated **combinational divider**.

Together with the multiplier and ALU, it forms one of the main execution paths of the Integer Unit.

## Data RAM

The processor contains **32-bit data RAM** for runtime data.

Load and store instructions allow programs to transfer values between the register file and RAM.

This makes it possible to operate on larger data structures such as arrays and enables programs such as sorting algorithms.

## Program Counter and Control Flow

The Program Counter determines the address of the next instruction.

During normal execution it advances to the next instruction. Branch and jump instructions can modify the next address, enabling:

- loops
- conditional execution
- jumps
- algorithmic control flow

## 7-Segment Output

The CPU includes an output system for displaying integer results using multiple **7-segment displays**.

A conversion circuit converts integer values into individual decimal digits, allowing multi-digit decimal numbers to be displayed rather than limiting the output to a single digit.

## Complete Program Flow

A program passes through the complete system as follows:

```text
Assembly source code
        │
        ▼
Python Assembler
        │
        ▼
32-bit Machine Code
        │
        ▼
Instruction ROM
        │
        ▼
Program Counter selects instruction
        │
        ▼
Control Unit decodes instruction
        │
        ▼
Register operands are selected
        │
        ▼
ALU / Multiplier / Divider / Memory
        │
        ▼
Result
        │
        ▼
Register File / RAM / Output
```

This allows the processor to execute complete programs rather than only individual hardware operations.

## Floating-Point Extension

A **Floating-Point Unit (FPU)** is planned as the next major extension of the architecture.

The ISA and assembler already contain definitions for floating-point registers and instructions. The next step is the completion and integration of the corresponding floating-point execution hardware into the CPU datapath and Control Unit.
