# 32-Bit CPU in Logisim Evolution

A custom 32-bit CPU designed and implemented in **Logisim Evolution**, featuring a custom **MIPS-inspired Instruction Set Architecture (ISA)**, a custom assembly language, and a **Python-based assembler**.

The project covers the complete path from writing an assembly program to executing the corresponding machine code on a simulated processor.

## Overview

The general execution workflow is:

```text
Assembly Program (.asm)
        ↓
Python Assembler
        ↓
32-bit Machine Code (.hex)
        ↓
Instruction ROM
        ↓
Control Unit
        ↓
CPU Datapath
        ↓
Registers / Integer Unit / RAM
        ↓
Output
```

Assembly programs are written using the custom instruction set and translated into 32-bit machine instructions by the Python assembler.

The generated machine code is loaded into the instruction ROM. The CPU fetches the instructions from ROM, while the Control Unit decodes them and generates the control signals required to coordinate the datapath, registers, memory and execution units.

## CPU Architecture

The CPU is divided into several functional units.

### Control Unit

The Control Unit decodes the current machine instruction and generates the control signals required by the rest of the processor.

It controls, among other components:

- register access
- execution-unit selection
- memory operations
- branches and jumps
- write-back
- Program Counter updates

### Register File

The processor provides 32 general-purpose 32-bit integer registers.

Two source registers can be read for an operation and results can be written back to a destination register.

The register naming scheme follows a MIPS-inspired convention, including registers such as:

```text
$zero
$at
$v0 - $v1
$a0 - $a3
$t0 - $t9
$s0 - $s7
$k0 - $k1
$gp
$sp
$fp
$ra
```

### Integer Unit

The Integer Unit is responsible for integer computation and combines several different types of operations into a common execution path.

It contains:

- Arithmetic Logic Unit (ALU)
- combinational multiplier
- combinational divider

The ALU itself integrates multiple operation categories, including:

- arithmetic operations
- logical operations
- comparisons
- shifts

This allows different types of operations to use a common interface within the CPU datapath.

### Multiplier

Integer multiplication is implemented using a dedicated **combinational multiplier circuit**.

### Divider

Integer division is implemented using a dedicated **combinational divider circuit**.

### Memory

The processor contains separate program and data storage.

The **instruction ROM** contains the machine code generated by the assembler.

The **data RAM** is used by programs to store and retrieve runtime data through load and store instructions.

### Program Counter

The Program Counter keeps track of the current instruction address and is updated according to normal sequential execution, branches and jumps.

### Output

The CPU includes a decimal output system using multiple **7-segment displays**.

32-bit integer values can be converted into their decimal representation and displayed as multi-digit numbers rather than only as individual hexadecimal digits.

## Instruction Set Architecture

The processor uses a custom **MIPS-inspired 32-bit ISA**.

The instruction set contains three main instruction types:

- R-Type
- I-Type
- J-Type

### R-Type

R-Type instructions are primarily used for register-to-register operations.

Examples:

```asm
add $t0 $t1 $t2
sub $t0 $t1 $t2
and $t0 $t1 $t2
or  $t0 $t1 $t2
mul $t0 $t1 $t2
div $t0 $t1 $t2
```

### I-Type

I-Type instructions contain an immediate value and are used for operations such as arithmetic with constants, memory access and conditional branches.

Examples:

```asm
addi $t0 $t1 10
lw   $t0 $t1 0
sw   $t0 $t1 0
beq  $t0 $t1 label
```

### J-Type

J-Type instructions are used for unconditional control-flow changes.

Example:

```asm
j label
```

Detailed instruction encodings and opcode/function assignments are documented separately in the project documentation.

## Assembly Language

Programs for the CPU are written using the custom assembly language.

A simple program may look like:

```asm
li $t0 10
li $t1 20

add $t2 $t0 $t1
```

The assembler also supports pseudo-instructions.

For example:

```asm
li $t0 10
```

is translated into an appropriate immediate instruction.

Other supported pseudo-instructions include operations such as:

```text
not
neg
inc
dec
```

The assembler also supports labels for control-flow instructions.

Example:

```asm
loop:
    dec $t0
    bne $t0 $zero loop
```

## Assembler

The assembler is implemented in **Python** and translates programs written using the custom assembly language into the 32-bit machine-code representation understood by the CPU.

The assembler consists of several components:

```text
assembler/
├── main.py
├── assembler.py
├── utils.py
├── program.asm
├── program.hex
└── dictionaries/
    ├── instructions.py
    └── registers.py
```

### `main.py`

Entry point of the assembler.

It reads the assembly source file, processes the instructions and writes the resulting machine code.

### `assembler.py`

Implements the actual instruction encoding.

It converts R-Type, I-Type and J-Type instructions as well as supported pseudo-instructions into their corresponding 32-bit machine-code representation.

### `utils.py`

Provides preprocessing functionality including:

- removal of comments
- removal of empty lines
- processing of labels
- preparation of the final instruction list

### `dictionaries/instructions.py`

Contains the definition of the ISA, including:

- instruction names
- instruction types
- operand formats
- opcodes
- function codes

### `dictionaries/registers.py`

Maps symbolic register names such as `$t0`, `$s0` and `$ra` to their corresponding 5-bit register addresses.

## Running the Assembler

Assembly source code is written in:

```text
assembler/program.asm
```

From the `assembler` directory, run:

```bash
python main.py
```

The assembler reads:

```text
program.asm
```

and generates:

```text
program.hex
```

`program.hex` contains the hexadecimal representation of the generated 32-bit machine instructions.

Example:

```text
5C014020
0C210000
0020003A
2008000A
F9000000
FD010000
```

The generated machine code is then loaded into the instruction ROM of the Logisim CPU.

The complete workflow is therefore:

```text
1. Write assembly code in program.asm

              ↓

2. Run:
   python main.py

              ↓

3. The assembler generates program.hex

              ↓

4. Load the generated machine code into
   the instruction ROM in Logisim Evolution

              ↓

5. Start / clock the CPU simulation

              ↓

6. The Control Unit fetches and decodes
   the instructions

              ↓

7. The CPU executes the program
```

## Floating-Point Support

Floating-point support is currently under development.

The ISA and assembler already contain support for floating-point registers and floating-point instruction encodings.

The assembler supports floating-point registers:

```text
$f0 - $f31
```

and defines instructions for operations such as:

```text
fadd
fsub
fmul
fdiv
fsqrt

feq
fne
flt
fgt
fle
fge

itof
ftoi
mtf
mff

flw
fsw
```

A floating-point immediate pseudo-instruction is also available:

```asm
fli $f0 2.5
```

The assembler converts the floating-point value into its **IEEE-754 single-precision representation** and generates the required machine instructions.

The next major development step is completing and integrating the **Floating-Point Unit (FPU)** into the processor datapath and Control Unit.
